# Original product shape

Rabbithole was conceived as a reader-first infinite canvas driven by a terminal agent. Selecting text creates a durable pending branch; answering materializes a child document; the same tree can be read fullscreen or explored spatially.

The proposal established the long-lived primitives: open or resume a Rabbithole, answer one pending question, list saved Rabbitholes, preserve concurrent asks, and export a frozen read-only view. It deliberately kept tree state in the product rather than asking an agent to manage it.

Later proposals added the web host, native PDF documents, human notes, portable artifacts, and a more explicit shared engine. Those additions supersede the original module plan while retaining its interaction model.
